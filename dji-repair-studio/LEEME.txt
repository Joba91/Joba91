DJI REPAIR STUDIO 1.7.0 — Windows 10/11 x64

Extrae el ZIP en una carpeta nueva y abre DJI REPAIR Studio 1.7.0.exe.
La aplicación mantiene una ventana, botones laterales y progreso medido.
La calibración óptica Mini 4 Pro / Air 3 todavía NO está implementada.

AIR 3 — PERFIL DE CONEXIÓN PENDIENTE
1. Conecta solo el Air 3 al PC y selecciona Air 3 en Modelo seleccionado.
2. En Visión de sensores se muestra 01.00.1600 como firmware declarado por el
   usuario. Corrígelo si DJI Fly muestra otra versión de aeronave.
3. Pulsa Recopilar perfil USB y guarda un ZIP nuevo Air3-PerfilUSB-....zip.
4. Comparte ese ZIP. Contiene el inventario de dispositivos/controladores de
   Windows, o el error completo si Windows no pudo devolverlo.

Esta acción consulta metadatos PnP del sistema. No carga el SDK DJI, no consulta
sensores ni envía peticiones de servicio, y no cambia controladores o modos.
Requiere Windows PowerShell incluido en Windows 10/11 y su módulo PnpDevice.
El 100 % significa que se leyó y guardó el inventario: la compatibilidad de
calibración permanece desconocida. El firmware se declara, no se lee del dron.

Air 3 es un destino independiente de Mini 4 Pro. Sus operaciones de sensores,
gimbal, fábrica y parámetros quedan bloqueadas mientras falte un perfil
contrastado. No se asigna automáticamente un código interno de otro producto.
Al cambiar entre ambos modelos se separan firmware y resultados de la vista.

MINI 4 PRO — RESULTADO DE LA PRUEBA RECIBIDA
El receptor 1.6.0 arrancó en el Windows del usuario y terminó con código 0.
El informe no contiene imágenes: hubo 48 tiempos de espera 0xd0010003 durante
10,209 segundos. Se confirmó estáticamente el significado de ese código en
la biblioteca recibida. No demuestra una avería, salud o calibración.
No hace falta repetir esa misma prueba para revisar el resultado ya recibido.

1.7.0 explica ese resultado y detiene estados nativos no interpretados. El
SDK puede informar pares conectados sin entregar imágenes. La referencia
Consumer también solicita arrancar un servicio de percepción antes de recibir;
el receptor 1.6.0 no hizo esa solicitud. Sus efectos y contrato de activación
siguen pendientes de validar. No se ejecuta automáticamente un script del dron.

RECIBIR IMÁGENES (PRUEBA) — MINI 4 PRO
Se conserva para el firmware declarado 01.00.1100. Usa un receptor propio x86
oculto y bibliotecas verificadas de DJIEngine de DJI Assistant 2 Consumer.
dbus_pc.json se lee junto a esas bibliotecas en su instalación original.
Los temas de referencia son raw/down/left y raw/down/right, 640x480/8 bits.
El perfil analizado configura una pareja inferior; no acredita cobertura del
sensor delantero derecho. Recibir imágenes no equivale a generar calibración.
El 100 % exige dos PGM verificados y el ZIP guardado. La inicialización del SDK
genera tráfico de control de efectos todavía no validados completamente.

OTRAS FUNCIONES
Mini 4 Pro conserva recepción pasiva MI04, consulta SN y diagnóstico HMS
experimentales. HMS admite registros 21/06 y 21/08; un código presente no prueba
que haya un fallo activo. Los campos no interpretados permanecen en bruto.
Las funciones previas de los otros modelos conservan sus límites y avisos.
No se añaden movimientos por ejes o una calibración nueva de IMU/gimbal.

VALIDACIÓN Y FUENTES
299 pruebas de aplicación/interfaz y 11 de empaquetado aprobadas. El EXE x64 se
comprueba bajo Wine con datos sintéticos y registros históricos, sin USB real.
El recopilador PowerShell pasa el analizador oficial 7.4.6 y una ejecución con
cmdlets sintéticos en Linux; aún requiere prueba con PnP real de Windows/Air 3.
El usuario ya acreditó el arranque x86 de 1.6.0. El kernel cloud no permite IA32;
el receptor 1.7.0 se verifica estáticamente y mediante adaptadores sintéticos.
No se ejecutan bibliotecas DJI en desarrollo ni se redistribuyen binarios,
configuraciones, registros o números de serie originales del usuario.
